# hl_ledger — HL 계정 입출금 표

Hyperliquid 계정 주소를 넣으면 그 계정의 **입금 → 내부 매매 → 출금·송금**을 표로 뽑고,
입금과 출금이 1:1로 이어지는지 판정한다. 프로젝트 파이프라인의 HyperUnit/HL 구간 Resolver.

공개 API만 쓴다 (인증 없음, 누구나 같은 결과).
Python 3.10+ 표준 라이브러리만 사용 — 설치할 것 없음.

## 실행

```bash
cd hl_ledger
python3 -m hl_ledger 0x3A37880ff9EbD7B45376Ef15bDA69Cefc0016575 --out out/case2      # 계정 1개
python3 -m hl_ledger --file tests/fixtures/case1_accounts.txt --out out/case1          # 여러 개 (79개 ≈ 1분 40초)
python3 -m hl_ledger --raw out/case2/raw.json --out out/case2                          # 저장된 원자료로 재분석
python3 -m pytest -q                                                                   # 정답 검증 (오프라인)
```

출력 (`--out` 폴더):

| 파일 | 내용 |
|---|---|
| `report.md` | 판정 + **사례 표 양식(단계 / tx / 연결고리 / 확실도 / 조회 경로)** + 입금·체결 요약·출금 상세 표. 노션에 그대로 붙여넣기 |
| `events.csv` | 원장 이벤트 전체 (Unit 매칭 시 원천·목적 체인 tx 포함) |
| `fills.csv` | 체결 전체 |
| `raw.json` | API 응답 원본 — 같은 결과를 다시 만들 수 있는 근거 |
| `summary.md` | 여러 계정일 때 계정별 한 줄 요약 + 판정·표식 집계 |

## 연결 방법

| 구간 | 데이터 | 연결고리 |
|---|---|---|
| 원천 체인 → HL 입금 | HyperUnit `GET /operations/{HL 계정}` | `sourceTxHash`(BTC tx:vout) ↔ `destinationAddress`(HL 계정). HL 원장 입금(송신자 Unit `0x574b…96fa`)의 `nonce` = Unit `destinationTxHash`의 nonce |
| HL 내부 매매 | HL `userFillsByTime` | 계정 단위. `@142`=UBTC/USDC 등은 `spotMeta`로 이름 해석 |
| HL → 외부 출금 | HL `userNonFundingLedgerUpdates` + Unit | HL 원장 출금의 `nonce` = Unit `sourceTxHash`(계정:nonce)의 nonce → `destinationTxHash`(ETH/SOL tx) |
| HL 내 송금 | HL `userNonFundingLedgerUpdates` (`send`/`spotTransfer`) | 받는 HL 계정 → 다음 홉 입력으로 그대로 사용 가능 |

## 판정 기준

| 판정 | 조건 |
|---|---|
| **확정** | Unit 입금 1건이 계정의 유일한 자금원 (그 외 유입이 입금 가치의 1% 미만) → 계정의 매매·출금이 그 입금과 1:1 |
| **계정 단위 확정** | Unit 입금 여러 건, 외부 유입 없음 → 계정 출금 전체는 이 입금들에서 나옴. 입금 건별 ↔ 출금 건별은 추정 |
| **추정** | Unit 외 자금이 1% 이상 섞임 (USDC 브리지 입금, 다른 계정 송금 등) |
| 해당 없음 | Unit 입금 기록 없음 |

표식 (판정은 유지, 세부 구분):
`소액 외부 유입` · `반올림 잔량` (입금 토큰 0.1% 이하 남음) · `미전환 잔액` · `입금 토큰 재매수` ·
`기록 누락 의심` (입금 = 매도 + 유출 + 잔액 검산이 안 맞음 — 대개 HL이 오래된 체결을 안 돌려줘서) · `선물 거래` · `유출 없음`

## 한계

- HL은 오래된 체결을 돌려주지 않는다. 대량 거래 계정은 매매 구간 수치가 하한값 (`기록 누락 의심` 표식으로 알림).
- Unit 원천 체인 금액 환산은 btc/eth/sol만 소수점 자리를 안다. 그 외 자산은 HL 수령량으로 표시.
- HL API 한도(분당 가중치 1200)에 걸리면 429 → 자동 대기 후 재시도한다. 원장 수십만 건짜리 거대 계정(예: HLP 볼트 46만 건)은 수 분 걸린다.
  일괄 조회 중 일부 계정이 끝내 실패하면 나머지는 계속 진행하고, `summary.md` 하단에 실패 목록을 남기며 종료 코드 1로 끝난다.
- 계정 소유자·귀속은 판단하지 않는다. "이 자금이 어디로 갔는가"만 답한다.
